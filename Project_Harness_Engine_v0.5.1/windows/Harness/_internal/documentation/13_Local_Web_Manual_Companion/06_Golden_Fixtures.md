Это тестовые данные для deterministic development; ни одна подпись `ACT-...` в fixture не является согласием живого оператора, ни один документ «архитектура готова» не доказывает соответствия реального проекта. Для real E2E advanced state формируется через существующий public kernel route с **реально проверенными** product results и subject-specific sources, без прямого редактирования `.harness`; затем UI tests продолжают из этого exact snapshot. Для fixture-only kernel test возможны отдельные ограниченные synthetic operator records; результаты не признаются production/Gate proof для другого проекта.

Validation при import: отсутствие документации сохраняет questions и `WAITING_INPUT`, не подставляет fake file; zip-unsupported `.txt` отмечается skipped; GPT extra field/fake approvals/egress **отвергаются**, нули в placeholder digest не позволяют пройти exact exchange binding в live Web. Fixture directory и `build` не содержат реальные user files/credentials.

`PYTHONPATH=src:. python local_web/fixtures/generate_advanced_state.py --output <new-empty-path> --test-only-synthetic-approval`. 
Создаёт тестовый Greenfield до accepted PROTOTYPE через public `next/verify/complete`, subject-specific operator fixture sources, `accept-stage` и затем public `start-maintenance`; `validate-project` подтверждает его внутреннюю консистентность.
