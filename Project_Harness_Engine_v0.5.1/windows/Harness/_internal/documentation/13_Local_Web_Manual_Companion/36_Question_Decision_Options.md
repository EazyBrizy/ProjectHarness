# Вопросы с готовыми вариантами решения

**Версия:** 0.5.1-WIP / NOT RELEASED  
**Дата:** 2026-10-25 (база документации v0.5.1)  
**Дата дополнения:** 2026-11-12

Новый анализ документов возвращает вопросы сразу с 2–3 вариантами решения,
описанием подхода, ограничениями и рекомендацией. Содержание зависит от проекта
и документов. Отдельного фиксированного набора ответов для конкретной предметной
области нет. Рекомендуемый вариант выделен, но не выбран автоматически.

После получения анализа варианты видны в предложениях на шаге 2. Сохраните
предложения анализа, как прежде; на шаге 3 кнопка «Выбрать этот вариант» одним
действием сохраняет ответ. Дополнительных confirmations/галочек нет. Можно
раскрыть «Свой вариант», ввести ответ и при необходимости изменить сведения в
обычной форме. Выбранные ответы сохраняются при перезагрузке и входят в следующий
пакет, чтобы модель учитывала уже принятые пользователем решения.

Вариант может содержать готовый ответ или способ получить недостающие сведения.
Во втором случае сохраняется подход, а вопрос остаётся открытым с прежней
обязательностью. Реальный бюджет, дата, доступы и другие неизвестные факты не
выдумываются. Выбор рекомендации не становится runtime evidence или формальным
approval. Будущие вопросы также имеют варианты; отвечать на них сейчас не
обязательно, они по-прежнему не блокируют текущую работу.

## Граница данных

Прямой CLI-анализ и ручной ZIP используют LOCAL_WEB_GPT_DRAFT_ONLY@4.
В questions добавлены choices, recommended_choice_id, recommendation_reason и
existing_unknown_index. Последнее связывает варианты с исходным открытым пунктом,
без размножения его формулировок. Варианты обязательны для каждого вопроса нового
формата. Максимум — 50 пунктов в bounded reply; прежние v2/v3 записи сохраняются
и читаются. Для старого результата без вариантов нужно повторить анализ.

Choice содержит title/description/tradeoffs, полный сохраняемый answer,
resolves_question и changes. SET задаёт точное значение поля, APPEND добавляет
записи в список, сохраняя прежние данные. До показа choices проверяются по core
schema и правилам draft. Поля execution, approvals, identity и управляющие
состояния недоступны; напрямую изменять unknowns, work_packages или skills
через choice нельзя. Нужные изменения unknowns выполняет сервер только для
вопроса, на который пользователь явно ответил. При неопределённом структурном
значении changes может быть пустым: содержательный ответ всё равно сохраняется
и передаётся следующему анализу.

POST interview/answers принимает ID сохранённого анализа/вопроса/варианта,
текущий fingerprint и idempotency key. Готовый вариант берётся из server record,
а не из присланного браузером patch. SET не перезаписывает связанные сведения,
изменённые после анализа; источники и revisions проверяются. Custom input также
проходит существующую проверку draft. GET/polling ничего не выбирают и не меняют.

Ответ хранится как digest-bound exchange record с provenance USER_ANSWER,
отдельно от предложений модели. Canonical write использует существующие public
draft update/commit API и durable intent/recovery; повтор того же запроса не
применяет изменения второй раз. Сохранённые ответы включаются в следующий pack
как INPUT. Смена документов помечает прежние ответы требующими пересмотра.

Новые механизмы не запускают model request при нажатии варианта и не выполняют
команды/задачи продукта. Фиксированный readonly CLI остаётся средством анализа
документов; Task executor, auto approvals и product file writes не включаются.
Проверяется только изменённый путь согласно [правилу целевой проверки](27_Targeted_Verification.md).
