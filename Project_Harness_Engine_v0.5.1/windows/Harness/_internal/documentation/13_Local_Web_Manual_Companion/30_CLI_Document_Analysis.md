# Анализ документации: Codex CLI или ручной пакет

**Версия:** 0.5.1-WIP / NOT RELEASED

**Дата дополнения:** 2026-11-10

## Выбор после загрузки ZIP

Откройте «Опрос и GPT». Загруженные документы можно разобрать двумя способами. Выбор категорий каждого файла и черновика больше не требуется. Следующие действия заменяют прежние шаги подготовки из главы 29; историческая глава сохранена.

### Автоматически через Codex CLI

1. Codex CLI должен быть установлен на этом компьютере. Если вход в Codex ещё не выполнен, запустите в терминале `codex login`. Harness использует существующий вход CLI; собственных аккаунтов и формы входа у Harness нет.
2. Нажмите «Подключить CLI». Приложение найдёт native `codex.exe`, проверит версию и наличие входа. Подключение сохраняется для приложения. Если нажать сразу «Анализировать документы через CLI», неподключённый CLI сначала проверяется автоматически.
3. Нажмите «Анализировать документы через CLI». Harness подготовит документы, передаст их CLI и покажет ход работы. Кнопка «Остановить анализ» отменяет этот запуск. Обновление страницы продолжает показ состояния и не запускает анализ повторно.
4. После завершения предложения модели появятся в браузере. Просмотрите их и сохраните нужные изменения существующим действием формы. Переносить JSON вручную не требуется. Оставшиеся вопросы обозначают сведения, которых модель не нашла в документах; их можно заполнить самостоятельно.

При отсутствии CLI, входа, изменении документов, ошибке формата или тайм-ауте приложение показывает причину. Можно устранить её и запустить новый анализ либо воспользоваться ручным пакетом. После обновления установленного CLI нажмите «Подключить CLI» повторно. Если приложение завершилось во время анализа, старый запуск показан как прерванный; автоматического повтора нет.

### Вручную через ChatGPT или Codex

1. Нажмите «Сформировать пакет вручную». Пакет создаётся одним нажатием, ссылки сразу появляются ниже.
2. Скачайте все части пакета и передайте их ChatGPT или Codex вместе с инструкцией из приложения.
3. Вставьте полученный JSON в поле ответа, просмотрите предложения и сохраните нужные изменения в черновике.

Ручной способ не требует подключения CLI. Подготовка пакета сама по себе не вызывает модель. Для обоих способов загрузка ZIP означает сохранение документов, а не завершённый смысловой анализ.

## Границы подключения

По отдельному заданию пользователя разрешены общее подключение CLI и автоматический анализ **только документации**. Это узкое дополнение к прежнему manual-only режиму. Подключение можно использовать при последующем развитии приложения, однако выполнение продуктовых Task/Run, изменение файлов продукта и полный `AUTOMATIC_EXECUTOR` сейчас не включаются. Их прежние ограничения и NO-GO сохраняются.

Browser обращается к фиксированным LocalWebService операциям. HTTP не принимает путь к программе, произвольные аргументы или команды. Исполняемый файл обнаруживается на компьютере и проверяется по SHA-256 перед запуском. Официальный launcher junction разрешается только при поиске CLI; правила путей проектов и загрузок не ослабляются.

CLI получает точное содержимое всех частей пакета через stdin. Используются `exec --ignore-user-config --ignore-rules --ephemeral --sandbox read-only`, фиксированные schema/output paths и ограниченный по времени дочерний процесс. Shell tools, изображения, web search, apps, plugins, skills discovery и multi-agent отключены; автоматическая загрузка проектных инструкций отключена. Команды из документов не исполняются. CLI может обращаться к своему провайдеру для анализа переданного текста. Harness не хранит учётные данные CLI, не добавляет внешний fetch/CDN/telemetry в браузер и не предоставляет shell/filesystem gateway.

Результат проходит существующие strict v2 binding/revision/schema checks и сохраняется только как `PREVIEW`. Смысловые утверждения модели остаются предложениями с происхождением. Автоматического commit, project approval или назначения Task/Run/Stage/Gate states нет. Отдельное действие сохранения предложений имеет собственный смысл и не является повторным подтверждением запуска.

## Данные, состояние и интерфейс

Упрощённый пакет помечается `UNCLASSIFIED`: приложение не объявляет документацию `PUBLIC` или `INTERNAL` вместо пользователя. Receipt фиксирует `EXPLICIT_ANALYSIS_ACTION` / `NOT_CLASSIFIED_BY_OPERATOR`. Существующий secret scan и явные ограничения проекта на `CONFIDENTIAL`/`SECRET` сохраняются; ошибка показана в форме. Прежний classified export API сохранён для совместимости, однако выбор категорий не навязывается в браузере.

Подключение хранит только executable path, SHA-256 и версию, без credentials. Jobs находятся в noncanonical app-data; разрешён один активный CLI-анализ. Повтор того же idempotency key не вызывает модель ещё раз. GET/polling только читают состояние. Отмена воздействует только на собственный процесс запуска. Ограничены размер входа/выхода, время и число сохранённых запусков. Raw stdout/stderr провайдера не выдаются через HTTP; временный wrapper ответа удаляется после проверки.

Новых modal dialogs, дополнительных обязательных галочек, local login или неактивных кнопок из-за незаполненных условий нет. Ошибки и инструкции показываются рядом с действием; кнопки блокируются только на время соответствующей работы.

## Проверка изменения

Проверяются только подключение, фиксированный process boundary, новые HTTP операции, повтор/отмена/прерывание/устаревание результата, два изменённых браузерных пути и упаковка изменённых файлов. Реальный CLI проверяется отдельно на синтетическом документе. Full engine/core regression и вся PH-LW matrix не запускаются. Успешный анализ документации не означает GO полного `AUTOMATIC_EXECUTOR` или release v0.5.1.

Сведения о CLI сверены с локальным `codex exec --help` / `codex login status` (0.154.0) и официальными материалами: [CLI](https://learn.chatgpt.com/docs/codex/cli), [non-interactive mode](https://learn.chatgpt.com/docs/non-interactive-mode), [config reference](https://learn.chatgpt.com/docs/config-file/config-reference), [Windows sandbox](https://learn.chatgpt.com/docs/windows/windows-sandbox). Подробные команды, hashes и результаты находятся в новом workspace-отчёте `CLI_DOCUMENT_ANALYSIS_2026-11-10`; исторические verdicts не переписаны.
