# Понятный порядок анализа документов

**Версия:** 0.5.1-WIP / NOT RELEASED  
**Дата:** 2026-10-25 (база документации v0.5.1)  
**Дата дополнения:** 2026-11-10

## Что делать после ZIP

В разделе «Опрос и GPT» основной экран показывает следующий шаг и число загруженных документов. Порядок работы:

1. «Подготовить пакет для анализа» → выбрать категории данных → «Создать пакет для анализа».
2. Скачать все файлы пакета, передать их ChatGPT или Codex CLI вместе с инструкцией. Harness сам модель не вызывает. Вставить полученный JSON в поле ответа, посмотреть предложения и сохранить их в черновике.
3. Уточнить оставшиеся вопросы. Их можно заполнить самостоятельно и до анализа моделью.

Загрузка документов означает только сохранение файлов. Она не создаёт результатов смыслового анализа. На обычном экране нет raw hashes, внутренних refs, revision/status codes и технических JSON-настроек шаблона. Эти сведения доступны в закрытом по умолчанию блоке «Технические сведения».

## Откуда берутся сохранённые сведения

Прежнее название «Известные ответы и provenance» заменено на «Сохранённые сведения о проекте». Это содержимое черновика, а не утверждение о достоверности фактов. Локальные значения обозначены «Сохранено в черновике проекта»; это не всегда доказательство того, что поле лично заполнил пользователь. Применённые ответы модели обозначены «Предложено моделью», с понятными названиями источников, когда они указаны. После изменения документов сохраняется предупреждение о необходимости пересмотра ответа.

Служебные значения шаблона `implementation.claimed_current_level`, `project.ambiguity_mode`, `skills.resolutions`, `profile.ref` не выдаются за содержательные ответы о проекте. Они остаются в данных и технических сведениях. Если содержательных ответов ещё нет, раздел прямо сообщает об этом.

## Представление и контракты

Подписи, названия шагов, статусы экрана, категории данных, история пакетов и результаты применения показаны по-русски. Canonical значения option/API, exact digests/refs, тело пакета и JSON-ответ модели не переводятся и не переписываются. Полный текст инструкции модели находится в отдельном раскрываемом блоке и доступен для копирования; он не загромождает основной экран.

Изменение ограничено представлением вкладки и текстом общего уведомления об обновлении. API, provenance computation, schemas, sources и state transitions не меняются. Не добавляются local login, повторные подтверждения либо automatic executor. Проверяются только два затронутых UI-сценария; полный прогон движка не выполняется.
