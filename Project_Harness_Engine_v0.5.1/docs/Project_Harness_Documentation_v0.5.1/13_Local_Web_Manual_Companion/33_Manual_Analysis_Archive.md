# Один архив для ручного анализа документации

**Версия:** 0.5.1-WIP / NOT RELEASED  
**Дата:** 2026-10-25 (база документации v0.5.1)  
**Дата дополнения:** 2026-11-10

## Порядок работы

Нажмите «Сформировать пакет вручную» в разделе «Опрос и GPT». Harness подготовит пакет и сразу начнёт скачивание `harness-analysis.zip`. В архиве два файла: `ИНСТРУКЦИЯ.md` с заданием для модели по-русски и `pack.md` со всеми документами, текущими сведениями, полными правилами, схемами и образцом JSON-ответа.

Прикрепите ZIP к ChatGPT или Codex для анализа. Модель должна прочитать инструкцию и полный pack.md, извлечь ответы из документации, оставить реальные пробелы вопросами и вернуть JSON для Harness. Вставьте ответ на шаге 2 и просмотрите предложения. Отдельный блок истории файлов, ручное скачивание частей и копирование инструкции убраны. Ручной способ не подключает CLI и сам не отправляет файлы внешней модели; автоматический CLI-анализ остаётся отдельным выбором.

Если исходный сохранённый пакет состоял из частей, при скачивании ZIP они проверяются и объединяются в единственный pack.md без обрезки текста, повторов заголовков и ссылок на отдельные части. Exact payload, return skeleton, IDs/revisions/hashes сохраняются. Внутри нового pack.md полная инструкция GPT_PREPARATION остаётся прежней; короткая служебная ссылка из старого интерфейса отдельно не копируется.

## Граница реализации

Создание export — прежний POST с exact fingerprint/idempotency key. Следующий GET `/api/projects/<project_id>/gpt/exports/<exchange_id>/archive.zip` только читает актуальный export, проверяет binding и hashes всех сохранённых файлов и собирает ZIP в памяти. GET не создаёт записей, не меняет canonical данные и не запускает модель. ZIP содержит только два фиксированных инертных MD; пути из документов в имена архива не попадают. Сохраняются request/Host/Origin/port guards, предел полного пакета 20 MiB, secret/restricted policy и strict preview. Старый parts download API и CLI consumer сохранены для совместимости.

В браузере POST и binary GET используют существующую очередь запросов. Ошибка сервера показывается в форме, JSON ошибки не сохраняется как ZIP; mutation автоматически не повторяется. Успешный ответ с неожиданным MIME также отклоняется. Подтверждений, consent-галочек или local login не добавляется.

Целевая проверка: ZIP/CRC/два файла, точный payload и binding, single/multipart UTF-8 объединение, read-only/replay, stale/tamper/foreign Origin, одно нажатие → одно скачивание в настоящем TCP/headless Edge, ошибки скачивания и совместимость JSON-preview. Full engine/core regression, вся PH-LW matrix и повторный реальный model analysis не выполняются. Это отдельно запрошенная функциональность ручного ZIP; сборка архивов поставки Engine/Documentation не требуется. Предыдущие exact-byte verdicts сохранены; automatic Task executor выключен, полная v0.5.1 NOT RELEASED.
