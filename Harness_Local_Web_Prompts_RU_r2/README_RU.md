# Как применять 12 промптов Harness Local Web

**Ревизия r2, 2026-11-01. Это подготовленный набор заданий, не готовый веб-интерфейс и не изменённый Engine.**

**PH-051-12 не принят:** «после PH-051-12» означает WIP snapshots из неуспешной финальной приёмки, с сохранённым NO-GO. Они пригодны как фиксированная база дальнейшей разработки при проверке применимых контрактов; это не разрешение на полный релиз или automatic execution. Уточнение и порядок действий: `BASELINE_CLARIFICATION_R2.md`.

Главное решение: небольшой native Windows launcher запускает локальный Flask/Waitress сервер и открывает браузер. MD/ZIP import, обмен с GPT, согласования, сборка и визуальный ручной lifecycle работают через проверяющее ядро Harness. Нет обязательного Python/Node/WSL/Podman у пользователя для подготовки.

## Содержимое

- `IMPLEMENTATION_PLAN_RU.md` — зафиксированная архитектура, scope, пути, UX, безопасность и порядок.
- `ALL_IMPLEMENTATION_PROMPTS_RU.md` — все 12 полных промптов в одном документе.
- `prompts/PH_LW_01.md` … `prompts/PH_LW_12.md` — самостоятельные промпты для отдельных диалогов. Общие ограничения уже повторены внутри каждого; вручную добавлять общий префикс не требуется.
- `CONTROL_MAP.md` — все 26 исходных CLI-операций и соответствующий visual route либо честная capability boundary.
- `ACCEPTANCE_MATRIX.md` — 36 обязательных E2E/security/recovery scenarios с пометкой PLANNED.
- `SOURCES_AND_BASELINE.md` — точные исходные ZIP hashes, прочитанные API/ограничения и первичные технические источники.
- `PACK_VALIDATION.json` — техническая проверка целостности именно этого набора промптов. Не отчёт о runtime/UI tests.
- `MANIFEST.sha256` — хеши файлов набора, кроме самого manifest.

## Один этап — один отдельный диалог

Для первого этапа приложить текущие **WIP Engine/Documentation snapshots из попытки PH-051-12 с NO-GO**, `PH_051_12_TEST_REPORT.md`, архив нормативных спецификаций и этот набор. Не требовать успешно принятого PH-051-12 в качестве условия начала разработки Local Web manual; не разрешать automatic execution и не скрывать старые blockers. Использовать полный текст `prompts/PH_LW_01.md`.

На следующих этапах приложить **пару ZIP, полученную после предыдущего PH-LW**, а не исходную PH-051-12 заново. Добавить исходные normative specifications, план Local Web и полный текст нужного промпта. Вместо переноса текста допустимо приложить файл промпта и написать:

> Выполни только PH-LW-XX по приложенному полному промпту. Используй последнюю проверенную пару Engine/Documentation после PH-LW предыдущего номера, план Local Web и неизменные спецификации v0.5.0/v0.5.1. Внеси изменения, проведи проверки и верни два обновлённых ZIP с отчётом. Не расширяй scope. Не засчитывай отсутствие Windows/Podman стенда как PASS.

XX заменяется текущим номером. Архив промптов — средство передачи контекста разработчику; конечный пользователь будущего приложения не обязан его распаковывать или выполнять из него команды.

После каждого этапа проверять report и SHA-256. Если есть новый FAIL или нарушен используемый manual/preparation contract, исправить тот же этап на его последних артефактах, не переходить дальше с заведомо сломанными contracts. Два явно унаследованных automatic release blockers сохраняются отдельно и не выдаются за успешно пройденные проверки. Отсутствие real Windows evidence допустимо как честный промежуточный NOT RUN, но блокирует финальный Local Web GO.

## Чего ждать на выходе серии

Один установщик `Harness-Setup-win-x64.exe` → локальная страница с загрузкой MD/ZIP → questions/GPT exchange → отдельные approvals → готовая папка и первый JIT. Вручную остаются решения/ответы и передача материалов внешнему GPT/Codex; YAML, распаковка и внутренние команды скрываются за проверенными действиями мастера.

До отдельного AI API scope смысловой опрос не становится полностью автоматическим в одном локальном окне. До отдельной Podman/egress acceptance автоматическое исполнение не получает GO. При этом manual preparation имеет отдельную проверяемую готовность.

Реальный EXE создаётся только Windows build job. Исходник упаковщика, Linux-прогон или скриншот интерфейса не заменяют native installer test. Не нужно запускать PowerShell с обходом политики, отключать SmartScreen/антивирус или вручную ставить WSL ради подготовки.
