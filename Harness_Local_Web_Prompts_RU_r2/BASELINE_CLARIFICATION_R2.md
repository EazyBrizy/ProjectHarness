# Уточнение r2 — исходная WIP-база и открытый NO-GO

**Дата:** 2026-11-01. **Изменение:** только тексты плана и промптов. Ядро не менялось; runtime/Windows/Podman tests не запускались. Это не отчёт о завершении PH-LW или PH-051-12.

## Как понимать текущий статус

PH-051-12 дал отчёт, тестовые результаты, точечное исправление и два WIP ZIP; обязательная финальная приёмка не пройдена. Нельзя называть этот результат «успешно завершённым PH-051-12» или «релизом v0.5.1». Фраза «после PH-051-12» обозначает происхождение файлов, а не положительный release verdict.

Открыты два разных вида работ: (1) реализация положительного governed per-Run egress, (2) фактическая security/integration приёмка на подходящем rootless Podman стенде с pinned image. Установка Podman сама по себе не реализует отсутствующий egress; green mocks не заменяют фактическую изоляцию.

## Рекомендуемый путь для текущей цели

Начать PH-LW-01 с текущей зафиксированной WIP-пары, сохранить её report и hashes, затем последовательно PH-LW-02…12. Local Web создаёт MANUAL_HANDOFF projects; документы, опрос, согласования и сборка не получают зависимости от automatic executor. Приёмка Windows/manual отдельная и ещё не выполнена.

На каждом этапе повторять применимые regressions и сохранять fail-closed automatic policy. Если найден дефект общего core, используемого manual route, исправлять его в допустимом этапе либо фиксировать блокер; нельзя считать любые ошибки безопасными потому, что база WIP. Финальное GO Local Web требует реального Windows installer/browser/security run.

Отдельный путь завершения automatic: реализовать и проверить положительный approval-bound egress → выполнить обязательные фактические Podman security/E2E tests → заново провести PH-051-12 на выбранной конечной паре → выпустить новый отчёт с реальным GO/NO-GO. Исторический NO-GO не редактируется. Если automatic исправления вносятся в другую ветку, до общей поставки требуется явная интеграция и повторная приёмка, не ручное смешение файлов архивов.
